# Design

## Context

ユーザーはPC上のどのアプリケーションで作業していても、思考を中断することなく素早くタスクや作業実績をObsidianに記録できる環境を求めている。
Windows標準の `Win+R` のように左手で瞬時に起動でき、リソース消費が少なく、Web技術（HTML/CSS）による柔軟なUIスタイリングが可能なWindowsアプリケーションが必要とされる。
詳細は `proposal.md` および各 `specs/*/spec.md` を参照。

## Goals / Non-Goals

**Goals:**

- **超軽量・高速起動**: メモリ消費を最小限（常駐時 30〜50MB程度）に抑え、グローバルホットキー押下から 50ms 以内にポップアップを表示する。
- **Webスタックによる洗練されたUI**: HTML/CSS/TypeScriptを活用し、ユーザーがスタイルやレイアウトを容易にカスタマイズできるようにする。
- **OSワイドのグローバルホットキー**: Windows API（`RegisterHotKey`）を利用し、アクティブウィンドウに関わらず左手操作しやすいショートカット（デフォルト `Win+Shift+Q`）で起動する。
- **安全なObsidianファイル直接書き込み**: Obsidian Vault内のMarkdownファイルを直接操作し、フロントマターの正確な生成およびデイリーノートへの時系列追記を実現する。
- **Obsidian標準設定との連携**: デイリーノートの保存先、日付書式、テンプレートに関して Obsidian コアプラグイン設定（`.obsidian/daily-notes.json`）を自動的に尊重する。デイリーノートは Obsidian の標準コアプラグインであるため、ランチャーアプリ側にデイリーノート独自の設定項目は持たせず、Obsidian 側の構成に完全に従う。
- **柔軟な拡張性**: 作業実績の追記見出し（タグ/セクション）やタスクプロパティ（見積もり、重要度等）を設定ベースで容易にカスタマイズ可能とする。

**Non-Goals:**

- Obsidianの内部プラグインAPIエミュレーション（Vault内のローカルMarkdownファイルシステムを直接読み書きすることで、Obsidian本体の起動有無に依存せず動作させる）。
- 複雑なノート閲覧・編集エディタ機能（本アプリは「高速インプット・キャプチャ」に特化する）。
- macOS/Linux対応（初期フェーズではWindowsに特化。ただしTauriを採用することで将来的なクロスプラットフォーム対応の余地を残す）。

## Decisions

### 1. アプリケーションアーキテクチャ: Tauri v2 (Rust + Web Frontend) の採用

- **検討した選択肢**:
  1. *Obsidianプラグイン*: Obsidianが常時起動している必要があり、かつバックグラウンド/最小化時にOS全体のグローバルホットキーをフックして前面に単独ポップアップを出す公式APIが存在しないため見送り。
  2. *Electronデスクトップアプリ*: Web技術でUIを作成できるが、Chromium+Nodeランタイムを丸ごと抱えるため常駐メモリが150〜300MB以上消費され、要件の「無駄にCPUやメモリを使う構成を避けたい」に反するため見送り。
  3. *C# / WPF*: ネイティブWin32 APIや低メモリには優れるが、UIスタイリングがXAMLに限定され、ユーザーの要望である「Webアプリのスタイル設定のしやすさ」を満たしにくいため見送り。
  4. *Tauri v2 (Rust + WebView2 + HTML/Tailwind/TS)*: Windows標準のWebView2ランタイムを使用するため実行バイナリが小さく、常駐メモリは約30〜50MB。RustによるネイティブWin32ホットキーやシステムトレイ、高速ファイルI/Oを安全に実行でき、UIはHTML/CSS/Tailwindで自由に調整可能。
- **決定**: **Tauri v2 (Rustバックエンド + Webフロントエンド)** を採用する。

### 2. ウィンドウライフサイクルとグローバルホットキー

- **ホットキー登録**:
  - Rustバックエンドで `tauri-plugin-global-shortcut` または Win32 `RegisterHotKey` を利用。
  - デフォルトキーバインド: `Win+Shift+Q`（左手だけで自然に押下可能で、Windows標準ショートカット `Win+Shift+S` [画面キャプチャ] や `Win+R` 等と競合しないキー）。
- **ウィンドウ動作**:
  - バックグラウンド起動時（常駐時）にウィンドウをあらかじめ生成し、非表示（Hidden）状態で待機。
  - ホットキー押下時: `window.show()`, `window.set_focus()` を呼び出して瞬時に前面化。
  - 非表示化: `Escape` キー押下、入力送信完了時、またはフォーカス喪失（`blur`）時に `window.hide()` を実行して前のアクティブアプリにフォーカスを戻す。
  - タスクトレイ（システムトレイ）アイコンから設定画面の呼び出しやアプリ終了が可能。

### 3. モード切り替えとUI設計

- **UI構成**:
  - 画面上部にタブ切り替え（`[1] 作業実績 (デフォルト)` / `[2] タスク追加`）。
  - キーボードショートカット `Ctrl+Tab` または `Alt+1` / `Alt+2` で即座に切り替え可能。
  - 送信ショートカット: `Ctrl+Enter` で即座に保存・ウィンドウ非表示。
- **初期表示モード**:
  - ホットキーによるウィンドウ表示時は、**作業実績入力画面（Worklog mode）をデフォルト** として開き、メモ欄の複数行テキストエリアに即座にオートフォーカスを当てる。
- **作業実績入力画面**:
  - メモ入力欄（複数行テキストエリア、オートフォーカス）
  - プレビューまたは直近のログ表示（オプション）
- **タスク追加画面**:
  - タイトル（1行テキスト入力、フォーカス初期位置、ファイル名として使用）
  - 依頼者（1行テキスト入力、プロパティ）
  - 締め切り（日付入力またはテキスト、プロパティ）
  - タスク内容（複数行テキストエリア、本文）
  - 設定されたカスタムプロパティ（数値、テキスト、ドロップダウン等）

### 4. Obsidianファイル生成・更新ロジック

- **タスクノートの生成**:
  - 出力パス: `{vault_path}/{task_folder}/{sanitized_title}.md`
  - ファイル名禁止文字（`\ / : * ? " < > |`）を自動置換（例: 全角やハイフン）。
  - 同名ファイルが存在する場合は `_{index}` を付与。
  - フロントマターフォーマット:

    ```markdown
    ---
    requester: 田中
    due: 2026-11-15
    completed: null
    ---

    タスクの内容
    ```

- **Obsidian コアプラグイン設定 (`.obsidian/daily-notes.json`) の自動連携**:
  - デイリーノートの解決にあたり、まず `{vault_path}/.obsidian/daily-notes.json` の存在を確認・読み込みする。
  - キーの解析:
    - `format`: デイリーノートの日付書式（例: `YYYY-MM-DD`, `YYYY-MM-DD(ddd)`）。Moment.js 構文に従う。
    - `folder`: デイリーノート格納先フォルダ（例: `Daily`）。
    - `template`: Vault内テンプレートファイルの相対パス（例: `Templates/Daily Note`）。`.md` 拡張子の有無に関わらずファイルを検索・解決。
  - 設定ファイルが存在しない、または各キーが未定義の場合は、Obsidianコアプラグインのデフォルト設定（日付書式: `YYYY-MM-DD`、格納フォルダ: Vaultルート、テンプレート: なし）へフォールバックする（ランチャーアプリ側にはデイリーノート用設定項目を持たせない）。
  - **Moment.js 互換日付フォーマット処理とロケール解決**:
    - 単純な部分文字列置換（`.replace("dd", ...)`）では `(ddd)` が `(08d)` のように誤破壊されるため、最長一致トークン置換またはトークナイザ処理を実施し、角括弧エスケープ（`[...]`）をサポートする。
    - 対象トークン: `YYYY`, `YY`, `MMMM`, `MMM`, `MM`, `M`, `DD`, `D`, `dddd`, `ddd`, `dd`, `d`, `HH`, `H`, `hh`, `h`, `mm`, `m`, `ss`, `s` など。
    - ロケール解決: `{vault_path}/.obsidian/app.json` 内の言語設定（`userLocale` 等）または OS のシステムロケールを参照。
    - 日本語ロケール時の曜日マッピング:
      - `ddd` / `dd`: `日`, `月`, `火`, `水`, `木`, `金`, `土`
      - `dddd`: `日曜日`, `月曜日`, `火曜日`, `水曜日`, `木曜日`, `金曜日`, `土曜日`
    - 英語ロケール時の曜日マッピング:
      - `ddd`: `Sun`, `Mon`, `Tue`, `Wed`, `Thu`, `Fri`, `Sat`
      - `dddd`: `Sunday`, `Monday`, ...
  - **デイリーノートへの作業ログ追記**:
    - 本日ノートのパス解決: `{vault_path}/{daily_folder}/{formatted_today}.md`（例: `YYYY-MM-DD(ddd)` → `2026-11-08(日).md`）
    - 既存ノートの存在確認: 解決されたファイル名でファイルシステムを探索し、既存ノートが存在する場合は新規作成せず、そのノートへ追記する。
    - ファイルが存在しない場合: 解決されたテンプレートを読み込み、日付プレースホルダーを本日日付に置換して初期ノートを生成。
  - **挿入位置解決ロジック（アンカーオプション対応）**:
    - **アンカー優先モード (`worklog_use_anchor: true`)**:
      - デイリーノートを行単位で走査し、`worklog_anchor_comment`（デフォルト: `%% worklog %%`）に一致する行を検索。
      - アンカーが見つかった場合、その**アンカー行の直前**にエントリを挿入し、アンカー行自体は次回追記のために保持する。
      - アンカーが見つからない場合は、下記の見出し走査へフォールバックする。
    - **見出し走査モード (`worklog_use_anchor: false`, デフォルト)**:
      - 設定された見出し文字列 `worklog_section_heading`（デフォルト: `## 作業ログ`）を行単位で走査。
      - 該当見出しを検出した場合、次の同レベル見出し（例: `## 振り返り`）が出現する直前、またはファイルの末尾にログを挿入。
      - 該当見出しが見つからない場合は、ファイルの末尾に `\n\n{worklog_section_heading}\n\n` を追加した上で追記。
  - ログエントリフォーマット（WebVTT風、タイムスタンプ + メモ + 空行）:

    ```markdown
    14:35
    レビュー依頼対応
    - PR #123 の確認

    ```

### 5. 設定管理 (Configuration)

- 設定ファイル配置場所: `%APPDATA%/obsidian-task-launcher/config.json`
- スキーマ構造:

  ```json
  {
    "vault_path": "C:/Users/.../ObsidianVault",
    "tasks_folder": "Tasks",
    "default_mode": "worklog",
    "worklog_section_heading": "## 作業ログ",
    "worklog_use_anchor": false,
    "worklog_anchor_comment": "%% worklog %%",
    "global_shortcut": "Super+Shift+Q",
    "auto_hide_on_blur": true,
    "task_custom_properties": [
      {
        "key": "estimate",
        "label": "見積もり (h)",
        "type": "number",
        "default": null
      }
    ]
  }
  ```

## Risks / Trade-offs

- **[Risk] グローバルホットキーの競合**
  → *Mitigation*: ホットキー登録時にエラーを検知した場合、システムトレイ通知および設定画面にて別のキーへの変更を促す。
- **[Risk] ファイル書き込み時のObsidianとの同期競合**
  → *Mitigation*: Obsidianはローカルファイルシステムの変更イベント（FileSystemWatcher）を常時監視して差分を取り込む仕様となっているため、ファイルロックを最小限（アトミックな一時ファイルリネームまたは迅速な追記書き込み）にすることで競合を回避。
- **[Risk] デイリーノートのセクション構造の予期せぬ変更**
  → *Mitigation*: 設定された `worklog_section_heading` が見つからない場合は、ファイルの末尾に安全にセクションを追加した上で追記するフォールバック処理を実装。
- **[Risk] `.obsidian/daily-notes.json` のフォーマット非互換**
  → *Mitigation*: パース失敗時やキー欠損時は安全にデフォルト値へとフォールバックし、書き込み不能エラーを防止。
- **[Risk] Windows WebView2ランタイムの依存**
  → *Mitigation*: Windows 10/11には標準でWebView2がプリインストールされている。万が一未インストールの環境ではTauriインストーラーが自動ダウンロードを案内。
